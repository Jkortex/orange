# 前言

在 Rust 服务中，即使没有哪个单独的查询看起来很慢，也没有哪个 CPU 图表显示异常，一次结账请求也可能会耗费两秒钟。在异步任务、下游调用和数据库等待之间的某个环节，时间悄然流逝了。这正是本书旨在解决的核心问题。

对于任何需要扩展、独立演进或在局部故障中存活的服务而言，分布式系统如今已成为默认架构。一次“立即购买”点击，在返回响应之前可能会触及数十个服务和多个数据存储。当其中某个环节变慢或失败时，问题很少仅限于“某个单一进程内发生了什么”。真正的问题在于：在这段旅程中，时间究竟消耗在了哪里？原因何在？

可观测性正是工程团队用客观证据代替主观猜测来回答这一问题的方式。追踪（Traces）展示了请求跨越服务的路径；指标（Metrics）展示了大量请求随时间变化的整体行为；日志（Logs）解释了导致某个请求成功或失败的具体事件。当这三种信号相互关联时，生产系统就不再是一个黑盒，而演变成一个能够解释自身行为的透明系统。

本书的核心在于在 Rust 中构建这种能力。Rust 已经成为后端服务、数据基础设施和高吞吐平台的有力选择，因为它提供了编译期内存安全、可预测的性能以及成熟的异步生态系统。这些特性同样使 Rust 成为实现可观测性的强大土壤：没有垃圾回收器引入的延迟抖动；所有权与借用机制让数据流向一目了然；异步运行时是显式的而非隐式黑盒，这意味着运行时本身也是可以被度量和推理的。

与此同时，对 Rust 服务进行良好的插桩（instrumentation）需要格外细致。在紧凑循环中添加 Span 可能会改变热路径性能，指标标签的基数也会带来实际开销；在异步边界间传播追踪上下文，需要深刻理解 Future 如何在任务之间流转。本书的目的就是向你展示如何在第一天就把这些事情做对，而不是在凌晨两点的突发线上故障中才去痛苦摸索这些细节。

本书的骨干是 OpenTelemetry——面向追踪、指标和日志的厂商中立标准。本书展示的每项技术所产生的遥测数据都遵循已发布的语义约定（Semantic Conventions），这意味着你可以将相同的数据路由到 Jaeger、Prometheus、Grafana、Loki、商业后端或它们的组合中，而无需重写插桩代码。你学到的是通用标准，而标准会伴随你在不同的雇主、云平台和技术栈之间迁移。

本书没有将可观测性当成孤立的特性清单来讲解，而是围绕一个真实运行的系统展开。我们将构建并插桩 OpenTel E-Commerce（OpenTel 电商系统），这是一个由 OtelMart 网关以及商品（Products）、库存（Inventory）和订单（Orders）服务组成的 Rust 微服务应用，使用 PostgreSQL 作为数据库，并以 Jaeger、Prometheus、Grafana 和 Loki 作为遥测技术栈。该系统被故意设计成会以各种真实且典型的方式发生故障：事务泄漏库存、查询在负载下性能劣化、连接池饱和、异步任务饥饿，以及促销流量暴露出隐藏的瓶颈。每一章都利用这个环境来讲解可观测性的某一层，并在随后的章节中不断重访，展示在真实事件中各层如何协同工作。

读完本书后，你将完成对一个完整分布式系统的插桩，诊断多个跨服务故障，通过 SLO 和错误预算将技术遥测与业务成果连接起来，并借助数据证据分析异步瓶颈与数据库争用。你还会将这一套基础应用到安全异常检测，以及将大语言模型（LLM）调用作为请求链路一部分的服务中。本书的目的不是教授某一个特定工具，而是为你建立一套持久的心智模型，使你能够将其应用到你所负责的任何 Rust 服务中。

## 本书读者对象

OpenTelemetry 最初可能会让人感到有些无所适从。

它引入了许多术语和组件，如果没有具体的系统作为依托，这些概念会显得彼此脱节。你可能读过关于追踪、指标、日志、上下文传播、Collector、Exporter 和采样的介绍，但在服务真正出现故障时，依然缺乏把握它们如何协同工作的信心。

本书通过在一个承受逼真压力的真实分布式系统中进行实战来弥补这一鸿沟，而不是通过罗列更多术语。

本书面向已经掌握 Rust 语言、并需要在实际生产排障中使可观测性发挥效用的 Rust 后端工程师、平台工程师和 On-Call 开发者。

本书内容绝非学术空谈，它扎根于作者在构建和运行高并发系统时亲身经历的各种挑战。这些经验塑造了每一章的案例与工程建议。

本书没有孤立地讲授可观测性概念，而是通过一个你可以亲自运行和“搞坏”的逼真应用来教授 OpenTelemetry。随着学习的深入，你将跟随请求跨越服务边界，观察关联在一起的追踪、日志和指标如何揭示系统的真实行为。该系统表现出的异常与真实生产系统别无二致。它的设计初衷就是贴近实战，而非教学上的无暇真空。

我们的目标不是解释名词术语，而是帮助你建立工程实战判断力。

所谓实战判断力，是指在故障发生的前三分钟内就知道该调取哪种信号，而不是耗费三十分钟用 grep 翻找日志导致排障方向走偏；是清楚知道慢查询、连接池饱和与锁争用在 Jaeger 中可能会产生完全相同的 Span 表现，并知晓用哪种补充信号来区分它们；是在追踪中出现相同的两秒空隙时，能够分清究竟是 Tokio 执行器陷入饥饿还是下游服务响应迟缓；是在领导询问故障造成的营收损失时，能够用看板数据而非凭空猜测来作答。

这种判断力来自于在压力下运维分布式系统，以及从踩坑犯错中领悟各种信号的真正内涵。本书提供了这样一个环境，并在每一步都详细推导背后的思考逻辑，而不仅仅是给出最终结果。

如果你是可观测性领域的新手，你将基于实际可运行的代码建立起坚实的心智模型；如果你已经掌握了基础知识，你将把这些概念与只有在真实系统中才会出现的复杂复合型故障联系起来。无论哪种情况，读完本书后，你都将掌握对任何 Rust 服务进行插桩、诊断和深入分析的能力。

读者需熟练掌握 Rust 基础知识：所有权、借用、基于 Tokio 的异步编程以及 Cargo 的基本用法。你不需要具备 OpenTelemetry 或任何特定可观测性厂商工具的先验经验。熟悉 PostgreSQL、HTTP 服务和容器技术有助于你更快推进实战部分，但书中在引入技术栈的每个组件时都会进行阐述。

## 本书内容概览

**第 1 章**，《可观测性导论》（*Introduction to Observability*），介绍为何可观测性对分布式系统至关重要，剖析一个贴近实际的电商案例，阐释追踪、指标和日志这三大支柱，并将 OpenTelemetry 定位为本书后续内容所依托的厂商中立基石。

**第 2 章**，《从追踪数据中读取 Rust 内存状态》（*Reading Rust Memory from Traces*），将 Rust 语言底层机制与你在生产环境遥测中实际看到的数据关联起来。内容涵盖栈与堆分配模式、Mutex 与 Arc 锁争用、Tokio 异步运行时行为、Send 与 Sync 保证，以及引用循环如何在长期追踪中体现为内存泄漏。

**第 3 章**，《OpenTel 电商系统》（*The OpenTel E-Commerce System*），介绍后续各章都会扩展的贯穿全书的实战案例。详细解析 OtelMart 网关以及 Products、Inventory 和 Orders 服务的架构设计、PostgreSQL 数据库模型、用于分布式事务的 Saga 模式、代码仓库组织结构，以及代码库当前的初始状态——目前仅依赖 `println!` 日志，完全缺乏真正的可观测性。

**第 4 章**，《请求全链路插桩》（*Instrumenting the Request Journey*），构建贯穿全书的核心遥测骨架。内容涵盖引入 `tracing` 和 OpenTelemetry 相关 crate、初始化 TracerProvider、设计统一的 Span 分类与命名规范、对 HTTP 边界进行插桩、跨服务传播追踪上下文，以及在 Jaeger 中可视化端到端分布式追踪。

**第 5 章**，《数据访问层插桩》（*Data Layer Instrumentation*），跟随请求深入数据库层。内容涵盖数据库 Span 的 OpenTelemetry 语义约定、设计稳定且低基数的 Span Schema、为 SQLx 的读查询、写查询和事务进行插桩、将数据库 Span 挂载到父级 HTTP Span 下，以及将连接池状态作为一等公民遥测数据暴露出来。

**第 6 章**，《核心指标体系（RED、USE 与 KPI）》（*Metrics That Matter (RED, USE, and KPIs)*），填补单个追踪链路与全集群宏观行为之间的鸿沟。阐明指标的本质，对比 Counter、Gauge 与 Histogram，详解聚合时序性（aggregation temporality），并演示如何实现面向请求的 RED 指标、面向资源的 USE 指标以及派生自追踪数据的业务 KPI，最后构建实用的 Grafana 看板。

**第 7 章**，《告别日志地狱的日志策略》（*Log Strategy Without Log Hell*），通过结构化且与追踪关联的日志补全三大支柱。剖析日志地狱的成因，介绍借助 `tracing` crate 和 JSON 输出实现结构化日志、通过 `trace_id` 和 `span_id` 将日志与 Span 强关联、有目的地选取日志级别、通过 OpenTelemetry Logs SDK 导出日志，以及将 Loki 与 Grafana 集成以实现多信号无缝跳转。

**第 8 章**，《基于遥测数据的商业智能视图》（*Business Intelligence Views From Telemetry*），通过服务等级指标（SLI）、服务等级目标（SLO）和错误预算，将技术遥测转换为业务语言。回答故障解决后销售副总裁常问的问题：我们损失了多少收入？能否保证在“黑色星期五”大促期间不再发生？本章引入 SLI、SLO 和错误预算作为将工程指标转化为业务语言的决策框架，为结账链路定义 SLI，计算错误预算，在 Grafana 中构建商业智能看板，并使用多时间窗口消耗率告警替代脆弱的静态阈值。

**第 9 章**，《利用火焰图定位性能瓶颈》（*Finding Bottlenecks with Flamegraphs*），弥合“知道瓶颈在哪里”与“理解代码为什么慢”之间的差距。使用 `cargo-flamegraph` 进行 CPU 剖析，使用 `jemalloc`/`jeprof` 进行堆内存剖析，演示如何解读火焰图以准确定位热路径和高频分配代码，然后使用发现问题的同一批追踪数据来验证修复效果。

**第 10 章**，《异步瓶颈与运行时饱和》（*Async Bottlenecks and Runtime Saturation*），深入剖析仅凭追踪无法解释的异步专属故障模式。内容包括在 Tokio 服务中将 I/O 等待、CPU 时间与调度器争用分离开来，使用 Tokio Console 进行任务级剖析，在 Axum 服务边界实现准入控制与过载保护（Load Shedding），构建异步压力看板，并通过案例分析揭示一个阻塞型后台任务如何在不触及任何下游服务的情况下使 Tokio 执行器陷入饥饿并恶化结账延迟。

**第 11 章**，《数据库瓶颈》（*Database Bottlenecks*），以一个缓慢的数据库 Span 为切入点，展示如何区分在追踪中表现相同的三种故障模式：慢查询执行、连接池耗尽和锁争用。通过连接池与等待状态信号扩展插桩，将应用侧 Span 耗时与数据库侧实际执行耗时对齐，并将数据库延迟与 SLO 影响关联起来。

**第 12 章**，《生产级故障排查实战》（*Debugging Production Incidents*），将完整的可观测性技术栈应用于排查一次症状与根因身处异处的复合型线上故障。促销流量下的结账性能劣化在定位到真正根因前经历了两次排查转向——根因是一个距告警点隔了三层调用栈的阻塞型后台任务。本章从中提炼出一套可复用的故障应急响应工作流、复盘报告模板以及可适配任何 Rust 服务的排障手册，并在结尾深入探讨了本书所构建可观测性技术栈的投资回报率（ROI）。

**第 13 章**，《在追踪中捕获安全攻击》（*Detecting Attacks in Traces*），复用同一套追踪基础设施来发现安全异常。内容包括对规范请求路径建模以检测跳过或重复的调用节点、在失败 Span 中识别凭证爆破模式、通过异常 Payload 大小检测数据外泄、部署拒绝服务（DoS）监控指标、实现应用级负载卸载，以及使用 OpenTelemetry Collector 尾部采样以低成本保留安全相关的关键追踪。

**第 14 章**，《AI 增强型服务的可观测性》（*Observability for AI-Augmented Services*），将可观测性模型延伸至在请求链路中调用大语言模型（LLM）的服务。涵盖面向生成式 AI 的 OpenTelemetry 语义约定、对调用 LLM API 的 Rust 欺诈评分服务进行插桩、Token 经济学与单次请求成本核算、诊断促销活动期间真实的 Token 爆炸故障、构建 GenAI 可观测性看板，以及针对第三方模型依赖的高可用弹性模式。

## 充分利用本书的学习建议

要完成书中的实操演练，你应该熟练掌握 Rust 基础知识，包括所有权、借用、基础生命周期以及基于 Tokio 的异步函数。你不需要预先具备 OpenTelemetry 的相关经验。本书会在相关概念出现时逐步介绍，除了解 Jaeger、Prometheus、Grafana 和 Loki 等工具的大致用途外，并不预设任何特定可观测性后端的深入知识。

示例项目 OpenTel E-Commerce 通过 Docker Compose 完全运行在你的本地机器上。跟随实操需要安装以下工具：

- Rust 1.8 或更高版本（通过 rustup 安装），包含 Cargo
- Docker 与 Docker Compose，用于运行 PostgreSQL 和遥测后端
- Git，用于克隆示例仓库
- 支持 Rust 的代码编辑器，例如带有 rust-analyzer 插件的 VS Code 或 RustRover
- 支持 Unix 风格命令的终端（在 Windows 上推荐使用 WSL2）

遥测技术栈（用于追踪的 Jaeger、用于指标的 Prometheus 和 Grafana、用于日志的 Loki）作为 Docker Compose 编排套件内置在示例仓库中。你无需云账号或商业可观测性服务即可完成所有章节的学习。

本书建议按章节顺序阅读，因为每一章都建立在前面章节添加的插桩基础之上。不过，完成第 1 章至第 7 章的基础构建后，你完全可以根据手头的排障需求或感兴趣的领域直接跳读后面的专题章节。第 8 章（SLO）、第 12 章（故障排查）、第 13 章（安全可观测性）和第 14 章（AI 增强型服务）在遥测基础就绪后，均可作为独立的参考指南来阅读。

如果你阅读的是电子版，建议亲自敲入代码，或从本书的 GitHub 仓库获取代码（https://github.com/PacktPublishing/Mastering-Distributed-Observability-in-Rust）。这样有助于避免复制粘贴代码时可能出现的潜在格式错误。
