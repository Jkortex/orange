# 站内搜索重构设计方案（Unified Smart Search）

> **文档版本**：v2.0（2026-09-23）  
> **设计目标**：消除前缀语法与模式割裂，打造直观、零门槛、现代化的全站统一搜索中心（类似 Raycast / Spotlight / Algolia DocSearch 体验）。  
> **底层引擎**：维持 Pagefind 纯前端构建期索引（`out/pagefind/`），保持零后端、零维护成本、极速加载优势。

---

## 一、现状痛点回顾

此前搜索方案的主要问题在于**“过度工程化”**与**“前缀语法阻碍”**：

1. **生硬的模式割裂与前缀认知门槛**：
   - 将搜索拆分为：普通搜索、`>` 命令模式、`@` 板块模式、`#` 或 `@toc` 大纲模式；
   - 访客只想搜索一篇文章或功能，却看到一排前缀快捷键（`> g c`、`@ g a`、`@toc g s`），不仅难以记忆，更造成了强烈的认知阻碍。
2. **缺乏自然联想搜索能力**：
   - 用户输入“暗黑”、“主题”搜不出切换主题的动作；输入“CSS”搜不出 CSS 分类页；输入本文章节名搜不到页内锚点。
3. **路由强绑定作用域带来负体验**：
   - 在文章页唤起搜索，自动绑定 `文章 ×` 标签，必须退格删除才能搜其他板块内容，阻断了探索路径。
4. **结果列表单调混排**：
   - 结果平铺，缺乏清晰的视觉分组（文章、章节、分类、操作混杂在一起）。

## 二、全新核心理念：统一自然搜索（Unified Smart Search）

```
┌────────────────────────────────────────────────────────┐
│ 🔍  输入关键词搜索全站内容、章节、分类或动作...        [ESC] │
├────────────────────────────────────────────────────────┤
│ [全部]  [文章]  [技能]  [生活]  [音乐]                  │ ← 直观分类胶囊
├────────────────────────────────────────────────────────┤
│ 📑 文章                                                │
│  ▸ 技术文章图表渲染指南：Mermaid 与架构图实践             │
│    ...命中摘要高亮：无论是算法分支、业务流转...             │
│                                                        │
│ 📍 本文大纲 (如果在文章详情页)                          │
│  ▸ 一、业务流程图（Flowchart）                          │
│                                                        │
│ ⚡ 快捷动作 (输入"主题"或"播放"即可匹配)                  │
│  ▸ 切换深浅主题                                        │
│  ▸ 播放全部音乐                                        │
├────────────────────────────────────────────────────────┤
│ ↑↓ 移动 · ↵ 打开 · Tab 切换分类                         │
└────────────────────────────────────────────────────────┘
```

### 1. 核心设计原则
- **零前缀心智（Zero-Prefix）**：单一输入框，输入任意字符即聚合搜索全站内容、页面大纲、分类与系统动作。
- **智能分组呈现（Grouped Results）**：搜索结果按业务类型清晰归类，高亮精准，层级一目了然。
- **直观的过滤胶囊（Filter Chips）**：替代隐蔽的路由绑定，用户可随时点按胶囊或按 `Tab` 键快速过滤。
- **优雅的空状态（Helpful Empty State）**：未输入时展示“最近访问”和“热门快捷入口”，不留冰冷空白。

## 三、界面与视觉系统规格

### 1. 对话框容器
- **位置**：视口顶部偏上（`top-20`），最大宽度 `max-w-xl`（约 576px），圆角 `rounded-2xl`，深层次毛玻璃阴影（`shadow-2xl`）；
- **层级**：`z-50` 顶层弹窗，遮罩背景微模糊（`backdrop-blur-sm bg-background/60`）。

### 2. 顶部输入框
- 左侧为简洁的放大镜图标，随输入状态变为品牌色；
- 输入框支持原生一键清空按钮；
- 占位符文案简洁自然：`"搜索文章、分类、大纲或快捷动作..."`；
- 右侧保留关闭按钮与 `ESC` 快捷键微标。

### 3. 分类过滤胶囊栏（Filter Chips）
- 位于输入框下方，常驻呈现：`全部` · `文章` · `技能` · `生活` · `音乐`；
- 激活态为品牌微底色 + 实色文本（`bg-primary/10 text-primary font-medium`）；
- 支持鼠标点击切换，或在输入框为空时按 `Tab` / `Shift+Tab` 快速轮换。

### 4. 搜索结果分组结构
当用户输入关键词后，内容实时聚合成以下四个清晰板块（有则展示，无则隐藏）：

1. **📑 文章与条目（Content Results）**：
   - 来源于 Pagefind 索引；
   - 展示：文章标题、发布日期/分类徽章、高亮摘要片段（`<mark>` 品牌高亮）；
2. **📍 本文章节（Outline / TOC）**：
   - 仅在文章或长文页面唤起时激活；
   - 动态扫描当前页面 `h2` / `h3` 标题，匹配项支持直接页内平滑滚动跳转；
3. **🏷️ 栏目与分类（Categories & Tags）**：
   - 匹配站点分类（如 CSS, Go, 架构等）；
   - 点击直达对应分类归档页；
4. **⚡ 快捷操作（Actions & Commands）**：
   - 匹配动作语义（如输入“主题”、“深色”、“明亮”直达主题切换；输入“播放”、“暂停”直达音乐控件；输入“首页”、“技能”直达导航）；
   - 回车直接执行对应动作并关闭搜索框。

### 5. 底栏操作指引
- 极简单行提示：`↑↓ 移动` · `↵ 打开` · `Tab 切换分类` · `Esc 关闭`。

## 四、交互流转与快捷键规范

| 操作 | 行为表现 |
|---|---|
| **Ctrl+K / Cmd+K** | 全局开合搜索对话框；打开即自动聚焦输入框 |
| **键入字符** | 逐字检索（无需防抖），即刻输出分组结果；竞态锁确保最后一次输入结果生效 |
| **清空输入** | 瞬间回到空状态（展示最近访问记录 + 热门推荐分类） |
| **↑ / ↓ 方向键** | 在整个结果列表（跨分组）中平滑循环移动高亮光标，选中项自动滚动进可视区域 |
| **Enter 回车** | 执行当前选中项（跳转页面、滚动到锚点、或触发主题/音乐动作）并关闭弹窗 |
| **Tab / Shift+Tab** | 在未开始在结果列表中移动时，快速循环切换分类胶囊（全部 ⇄ 文章 ⇄ 生活...） |
| **Esc / 点击遮罩 / 关闭按钮** | 立即关闭搜索框；焦点无缝回退到此前触发处 |
| **重新打开** | 智能保留上一次搜索词与结果（符合 Spotlight 心智，避免误关重输） |

## 五、空状态设计（Empty State）

在打开对话框且输入框为空时，不留白，展示具有高实用价值的内容：

1. **🕒 最近访问（Recent Visits）**：
   - 记录用户最近在博客中浏览过的 3~4 篇文章；
   - 点击直接重访，右侧带极简清除按钮；
2. **✨ 推荐分类 / 常用动作（Quick Suggestions）**：
   - 快速导航至“最新文章”、“技能清单”；
   - 一键触发“切换深浅主题”。

## 六、组件架构拆分规划

重构后代码结构将精简收敛为职责明确的子模块，不再引入反直觉的前缀模式：

```
src/components/chrome/search/
├── search-dialog.tsx       # 搜索主容器：对话框生命周期、快捷键监听、状态编排
├── search-input.tsx        # 顶部搜索栏：输入框、清空按钮、关闭触发
├── search-filter-tabs.tsx  # 分类过滤胶囊栏（全部/文章/生活/音乐）
├── search-results-group.tsx# 分组结果渲染容器：文章、大纲、分类、动作分组
├── search-empty-state.tsx  # 空状态视图：最近访问 + 推荐动作
├── search-actions.ts       # 快捷动作注册表（主题切换、音乐播放、快速导航）
└── use-search-engine.ts    # 搜索执行逻辑 Hook（Pagefind 全文检索 + 内存聚合过滤）
```

## 七、实施与验证计划

1. **第一阶段（已完成）**：彻底清除原 `search/` 复杂前缀代码，保留稳定纯净的 Pagefind 检索底座；
2. **第二阶段**：按照本方案编写高内聚组件，接入分组渲染与分类过滤胶囊；
3. **第三阶段**：编写针对统一智能搜索的端到端交互与无障碍测试用例；
4. **第四阶段**：全站静态构建与真实多端尺寸验收。
