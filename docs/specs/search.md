# 站内搜索功能规格（search）

> 状态：已确认（2026-09-14）
> 上位：`docs/specs/ui-ux.md` §1（搜索是全局 chrome）。本文定行为与边界，不定技术实现。
> 数据源：构建期 Pagefind 索引（`postbuild` 生成 `out/pagefind/`），纯前端、无后端、零成本。

## 1. 范围

1. 搜索覆盖全站已发布内容页（文章、专辑、分类、标签页均在索引内）。
2. 搜的是标题与正文；音频内容本身不可检索（专辑靠标题/艺术家/文案命中）。

## 2. 唤起

1. 两种等效入口：顶栏搜索图标按钮（图标化三判据，`aria-label="搜索"` + 悬停提示）与 Ctrl/Cmd+K 快捷键（按钮以 `aria-keyshortcuts` 标注）。
2. 打开后输入框立即聚焦，用户可直接键入。

## 3. 输入与检索

1. 逐字检索：输入变化即搜，不设搜索按钮、不设防抖（本地索引足够快）。
2. 竞态守卫：连续输入时只采用最后一次请求的结果，先到的慢响应不得覆盖后输入。
3. 大小写与前后空格不影响检索（关键词判空用 trim）。

## 4. 结果呈现

1. 每条结果 = 标题链接 + 摘要（含 `<mark>` 命中高亮，语义 token 重绘，不引入 Pagefind 默认样式）。
2. 标题链接指向内容页（站内路由）；点击后对话框关闭、页面跳转（播放不受影响）。
3. 结果列表键盘可达（Tab 逐条聚焦）；回车打开聚焦项（浏览器原生链接行为）。
4. 新结果到达前保留旧结果，不闪空、不抖动。

## 5. 状态与空态

1. 未输入：提示"输入关键词搜索全站内容"。
2. 清空输入：回到未输入态（结果清空）。
3. 无命中：明确"没有找到相关内容"，不留白。
4. 索引缺失（dev 未构建）：明确"搜索索引不可用，请先完成构建"，不抛错。
5. 检索异常：明确"搜索出错，请稍后再试"，结果区不残留旧数据。

## 6. 关闭语义

1. 四种等效关闭：Esc、点击遮罩、关闭按钮、再次 Ctrl/Cmd+K。
2. 关闭后焦点回到唤起处（触发按钮），键盘用户不迷路。
3. 关闭不清空搜索态：再次打开保留上次关键词与结果（类 Spotlight 行为）。

## 7. 索引构建

1. `postbuild` 对 `out/` 全量建索引，产物随站点一同部署；新增/修改内容下次构建自动入索引，无需手工维护。
2. 中文按字切分可检索即达标；不做词干、拼音、模糊纠错。
3. 不用 filters/sorts 等高级索引能力（当前无按面筛选需求）。

## 8. 安全

1. 摘要富文本来自自有构建期索引，仅含 `<mark>` 高亮标记；渲染前不引入第三方 HTML，无注入面（现状 `dangerouslySetInnerHTML` 的安全性说明见代码注释）。

## 9. 响应式

1. 对话框窄屏可用：不超出视口、结果区内部滚动、关闭按钮可达。

## 10. 不做什么（v1）

1. 不做方向键在结果间移动（Tab + 回车已完整可达）。
2. 不做搜索历史、热词、联想补全。
3. 不做跨内容类型筛选器（分类/标签页本身即聚合入口）。
4. 不做防抖/节流（§3.1）。

## 11. 技术选型：Pagefind（维持）

**结论**：维持 Pagefind，不自建 JSON + fuse 索引。

| 候选 | 结论 |
|---|---|
| **Pagefind**（构建后索引 + 动态 import 懒加载） | ✅ 采用。分片索引不随文章数线性膨胀首屏；中文开箱可用；`src/lib/pagefind.ts` 懒加载 + 缓存（含 null 缓存，dev 免重复失败），打包器忽略标注防静态解析 |
| 自建 JSON 索引 + fuse.js | ❌ 不用。全量索引进首屏包，规模上去后劣化；中文分词另起成本 |

## 13. 验收口径

自然语言断言：「Ctrl+K 开合」「输入即出结果且慢响应不覆盖」「空词回提示」「无命中/无索引/异常各有文案」「关闭再开保留上次搜索」「Esc/遮罩/按钮/快捷键四种关闭」「关闭后焦点回触发按钮」。
