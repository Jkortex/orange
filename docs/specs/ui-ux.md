# UI/UX 原则规范

> 状态：已确认（2026-09-14）
> 范围：只定原则（布局意图与交互意图），不定技术实现（不限定具体像素、布局手段、类名、组件结构）。
> 与代码的关系：本文是判定标准，现有实现与本文不一致时以本文为准、改代码不对齐本文不算完成。
> 细则归属：无障碍细则、主题变量结构等工程纪律仍在 `AGENTS.md`；各功能的行为细节在 `docs/specs/` 各分篇。

## 0. 产品基调（已定）

1. **极简阅读优先**：装饰最少、层级最少，音乐等模块不抢夺阅读视觉。
2. **音乐是完整小播放器**：播放体验按完整播放器验收（播放 / 暂停 / 上下首 / 进度 / 时间 / 关闭），允许引入第三方库，前提是不破坏纯静态、无后端、可多主题。
3. **移动触摸与桌面同等优先**：触摸交互与窄屏布局不是降级附带，而是与桌面同等验收，发布前需真机验证。

## 1. 全局布局原则

1. 全站只有一套骨架：顶栏、内容区、页脚，外加全局播放条与全局搜索。页面切换只换内容区，骨架不重排、不闪动。
2. 顶栏常驻：品牌、主要导航（首页 / 文章 / 音乐 / 技能）、搜索入口、主题入口。顶栏自身全宽两端对齐（品牌居左、导航与工具居右），不随内容区收窄；内容区仍按 §1.5 宽度克制。
3. 顶栏滚动时保持可见：长文滚动中途用户仍能一步触达导航与搜索，不必先滚回顶部。顶栏本身高度克制，不挤占阅读视口。
4. 窄屏不断功能：导航项不折叠隐藏；右侧组允许换行（两行顶栏），各项仍可达。
5. 页面只有一根主滚动：窗口级纵向滚动；内容区不设内部滚动容器，不出现双层滚动条。横向滑动只允许出现在分类 chips 这类本就横向的部件上。
6. 内容宽度克制：默认页面收窄居中、保证行长易读；需双栏的页面（文章分类浏览、技能包、带目录的长文详情）用宽容器。新增页面按此二选其一，不自创新宽度。
7. 播放条是悬浮的全局 chrome：不占用文档流、不把页脚顶上去；滚动到底时允许盖住页脚下缘；没有播放队列时完全不出现、不预留空白。
8. 搜索是全局 chrome：顶栏入口与键盘快捷键等效，打开后聚焦输入，结果可键盘操作、可关闭返回原位。

## 2. 页面组织原则

1. 首页是统一混合时间线：全类型按时间倒序混排，不分区、不设区块标题党；新增内容类型自动入流，不改首页结构。
2. 条目呈现全站统一骨架：类型标识 + 标题 + 关键元信息。同一概念在首页、分类页、标签页不得有三种长相。
3. 文章浏览是"分类 × 条目"：分类是过滤器（默认"最近"即全部），切换即时、无跳转、无加载态；分类清单由内容自动聚合，不手工维护。
4. 内容详情页极简：标题、日期、标签之后直接正文，不设侧栏，正文排版只服务可读性。
5. 详情页必有明确返回路径：正文顶部提供指向父级集合的文字返回（如"← 文章列表" / "← 音乐"），指向确定路由而非浏览器历史；浏览器自带返回仍可用，但不作为唯一路径。
6. 长文目录放右侧栏：达到篇幅的长文在正文右侧设目录栏（桌面端 sticky 跟随），窄屏叠放正文上方；点击锚点跳转。不做滚动高亮（scroll-spy），保持极简；后续需要再修订本文。
5. 音乐按专辑组织：一篇内容即一张专辑；专辑列表是网格浏览，专辑详情是"信息头 + 曲目表 + 文案尾"；曲目顺序即播放顺序。
6. 分类与标签职责分离：分类是单归属栏目（导航维度），标签是自由多标签（检索维度），两者不在界面上互相替代展示。

## 3. 阅读与视觉原则

1. 信息层级扁平：标题、元信息、正文三层足够，次要信息一律弱化，不加粗、不抢色。
2. 主题语义化：界面只表达"背景 / 前景 / 弱化 / 强调 / 边框"等语义，不表达具体颜色；新增主题只加定义，不改组件。
3. 对比度先行：正文与关键操作必须满足可读对比度，选色前验算而不是上线后返工。
4. 图标只用于操作：通用隐喻（播放、搜索、明暗等）且空间紧凑的操作可用图标；品牌、标题、正文、导航标签永不用图标代替文字。图标按钮必须有文字兜底（无障碍名与悬停提示一致），触摸设备上提示不得拦截点击。
5. 动效克制：只允许状态过渡类微动效，不做装饰性动画；动效不得承载信息（信息必须在无动效时完整可达）。

## 4. 交互原则

1. 所见即所得的即时性：分类切换、主题切换、播放状态切换都是即时反馈，无确认框、无整页刷新。
2. 播放不中断：页面跳转不打断播放；刷新丢失队列可接受，但站内导航必须连续。
3. 状态处处可见：当前播放曲目、当前分类、当前主题，在界面上都有明确指示，不让用户猜。
4. 键盘完整可达：所有操作（搜索、播放控制、分类、主题）都可用键盘完成；对话框可开可关、焦点行为正确。
5. 触摸同等可用：触摸目标足够大；任何功能不得只在悬停时出现；悬停提示在触摸设备上不得吞掉首次点击；发布前用真实触摸设备验证，而不是只看桌面浏览器。
6. 空态与降级有文案：无内容、无结果、无索引、加载失败，每种都有明确中文提示，不留白屏、不抛 raw 错误。
7. 回到顶部是全局部件：滚动超过一屏后出现，不常驻占位；位置固定一角且避让播放条，不遮挡正文操作；键盘可达、有文字兜底；动效尊重减少动态偏好（偏好开启时直接跳转、无平滑滚动）。
8. 悬浮部件互不打架：播放条、回到顶部、搜索框三者同时出现时各就其位、可分别操作，窄屏下回到顶部给播放条让位。

## 5. 音乐播放原则（完整小播放器）

1. 播放条必备能力：上一首 / 播放·暂停 / 下一首 / 进度（可拖拽、可键盘调节）/ 当前时间与总时长 / 关闭。缺任何一项即不完整。
2. 专辑卡可直接播：不进详情页即可播放整张专辑；正在播的专辑其按钮呈"暂停"态，再点即暂停而非重播。
3. 专辑详情可"播放全部"也可从任意单曲起播；当前播放行高亮并有明确指示。
4. 进度诚实：拖拽、键盘调节、自然播放三者一致；元数据缺失（如时长未知）时如实表达，不编造。
5. 第三方库可用，但必须同时满足：纯静态导出可用、无后端、样式可用语义变量重绘、多主题联动不断。

## 6. 响应式原则

1. 窄屏做减法不断功能：分类列表变为横向滑动、专辑网格变为单列、播放条精简为核心控制，但任何功能在窄屏都仍可达。
2. 能力判断不用宽度代替：触摸与否看设备能力，不看视口宽度（大屏触摸设备同样按触摸验收）。
3. 断点只表达"何时换排布"，不表达"何时砍功能"。

## 7. 不做什么

1. 不做服务端个性化、不做登录、不做评论等后端功能。
2. 不做装饰性主题（质感、渐变、阴影秀）；主题只换语义配色。
3. 不为单页面发明新布局语言；新需求先映射到上述六节，映射不上才修订本文。

## 8. 验收口径

1. 每条原则的验收都是自然语言断言（如"无队列时页面底部无播放条 reserved 空白"、"分类切换不发生路由跳转"、"触摸设备首次点击即执行功能"），不依赖具体 DOM 或类名。
2. 桌面浏览器验收 + 真实触摸设备验收双轨，触摸问题不靠桌面推断结案。
3. 与功能规格的关系：本文定"应不应该"，`player.md / search.md / content-model.md` 定"怎么做、边界是什么"；两者冲突时以本文为准并同步修订。
